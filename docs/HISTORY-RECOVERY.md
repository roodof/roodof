# Desktop history recovery — 0.9.13 local candidate

Settings reviews a trusted backup using the existing format-1 validator, prepares a new child folder under an explicitly chosen local parent, and requires a fresh preview plus boolean confirmation before restoration. Current data and original agent logs are never replaced. The existing CLI backup contract remains unchanged. Recovery is available without a successful source scan; demo writes are refused.

One bounded backup remains in memory for at most ten minutes. Preview/destination revisions are opaque, session-local and reject older requests. Destination directories are generated by PLER, outside current data/application subtrees; existing targets, network/device/reparse paths and malformed/unsupported archives are refused. Restore reuses the staged, fixed-file, fsync validator. If post-publish directory sync fails, a result is exposed only after all fixed restored bytes match the preview; persistence across power loss is then uncertain.

Authenticated GET /api/usage/recovery returns local status. Same-origin authenticated POST /api/usage/recovery/preview admits one bounded octet stream; POST /api/usage/recovery accepts closed JSON action schemas with duplicate/type/length rejection. No raw exception, backup bytes or original transcript enters the response. Local settings deliberately show user-selected destination/data paths. One backup/recovery admission lock and the existing application-action lock serialize operations; switching refuses later mutations.

Opening a recovered folder is a separate confirmed desktop action. The owner closes the old Electron window, dashboard, budget monitors and HTTP requests before changing the process-local data selection and creating a new server/window. If readers cannot drain within the bounded wait, the process exits instead of mixing folders; normal desktop users can reopen the remembered selection. No model, provider account or new executable command is introduced.

Normal desktop launches (without --data-dir, PLER_CACHE_DIR or a demo dashboard) read one non-chained desktop-history.json selector in the original default data root. Selected/previous absolute local paths are kept in that private atomic file, outside normal reports and backup format 1. Missing selection opens the starting root with an explicit warning; malformed files are preserved and need support before a new persistent selection can replace them. Explicit folder/environment launches bypass that selector and switches last for that run only. Terminal/status-line commands keep their original folder scope. Return to previous history swaps selection without merging or deleting either folder; switching is not rollback of user edits.

The sandboxed preload exposes only an additional fixed native directory picker, authorized for the owning top-level app frame. No file reader, shell, arbitrary IPC or child-frame access is exposed. Original logs, disposable caches, the history selector, machine-specific source-folder choices and reconnection undo journals are not added to the backup. Re-add custom log folders after recovery. Old PLER versions do not read the new desktop selector.

The application source remains private and this candidate is not published. Windows executable signing/license decisions remain separate. Clean Windows, actual agent/WSL histories, physical failure and user/accessibility acceptance remain Q01, the final task.
