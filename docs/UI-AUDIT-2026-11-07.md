# UI foundation audit — 7 November 2026

Baseline: 0.7.0, before the monochrome refactor. Measured from current source, not inferred from a marketing screenshot.

1. `src/pler/web/workspace.css`: 25,162 bytes and203 hex occurrences. Several independent workbench patches redefine the same body, sidebar, button and dialog selectors. There is no single token authority.
2. `src/pler/web/app.css`: main36px44px, panel24px26px; workspace dialog24px and empty chart50px. This consumes useful record area despite the compact session page.
3. `frontend/sessions-grid.css`: literal green, cream and blue-grey values diverge from the app palette; state colors also carry ordinary chrome.
4. `frontend/workspace.js:show`: one200ms translated fade; sidebar selection changes class immediately. No shared-layout indicator or physical selection.
5. `frontend/workspace.js:segmented`: DOM buttons change aria state immediately with no motion; button dimensions vary between stylesheet revisions.
6. `frontend/sessions-grid.js`:80px rows consume space for two metadata lines. Numbers have a monospace font but no shared numeric typography contract.
7. `frontend/workspace.js`: chart label/grid/bar colors are hard-coded independently of surrounding surfaces. Theme changes cannot stay coherent.
8. `src/pler/web/index.html` and workspace CSS: dialogs share a heavy floating-window treatment while the inspector has a separate edge/padding/shadow system.
9. `src/pler/web/app.css` and workspace CSS: button, select, checkbox, disclosure and file controls do not share complete hover/pressed/focus/busy states.
10. `frontend/workspace.js`: command palette only accepts one downward navigation step; list motion and keyboard interaction are not designed as one primitive.
11. `src/pler/web/index.html`: plain-text empty results and initial loading rely on progress/text, with no stable placeholder surface or specific keyboard action cue.
12. `frontend/workspace.js`/CSS: fonts, eyebrow labels and repeated scope paragraphs compete with the user's session identity. Empty work appears as a long settings form.

The current brief bans gradients/neon and boilerplate grids. Those are regression exclusions;
this baseline does not contain purple neon blobs, so that would be an invented audit finding.

See ../DESIGN.md for locked values and component contracts. The first implementation covers
tokens, core shell/primitives, actual spring/layoutId controls and coherent surfaces on all five pages.
